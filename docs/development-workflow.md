# U Link 开发工作流

本文件把根目录 `DEVELOPMENT_PRINCIPLES.md` 落到日常开发动作里。后续前端、小程序、PayloadCMS 后台、支付、会员、认证和内容发布相关改动，都按这里执行。每次提交前可使用 `docs/development-checklist.md` 做快速自查。

## 开发前

- 先确认当前改动对应的用户流程：用户从哪里进入、看到什么、点击什么、会创建或更新什么数据、下一步归哪个页面或服务负责。
- 区分原型、开发 demo、fixture 和生产路径。假内容只能出现在明确标记的原型、本地 demo 或测试 fixture 里。
- 涉及订单、会员、支付、认证、手机号、学校班级数据、内容发布状态时，先确认数据所有权和生命周期，再写接口或页面。
- 不为了适配现有接口形状而创建正式业务记录。浏览、预览、草稿和确认提交必须分清。

## 实现中

- 后端服务层先表达业务规则，再由 Next route handler 适配 HTTP 请求。
- 小程序端通过统一 API wrapper 调用后台，不在页面里散落请求细节。
- 生产路径不能用前端 fallback、默认值或假数据把失败伪装成成功。
- 空状态、加载失败和未开放状态要真实显示，不用“看起来有内容”的文案遮住后台未配置或接口失败。
- 跨页面传递稳定引用，例如内容 ID、订单号或服务入口 ID；进入页面后由页面自己读取拥有的数据。
- 支付、会员、认证等高风险状态以服务端持久化结果为准，小程序按钮返回成功不等于业务生效。

## 持久化要求

- 生产 PostgreSQL 必须是独立持久化资源，不跟随应用重新部署、镜像重建或容器替换而清空。
- PayloadCMS 上传、内容封面、附件、学校素材和合作方资料必须使用 COS 或明确对象存储，不能把应用本地目录作为唯一数据来源。
- `PAYLOAD_SECRET`、数据库密码、微信 AppSecret、微信支付私钥、APIv3 密钥、COS 密钥和短信密钥只能来自环境变量或密钥管理。
- 数据迁移、批量导入、支付相关改动和生产发布前必须有备份和回滚思路。

## 提交前检查

普通后台或业务接口改动至少执行：

```bash
pnpm verify:cms
```

涉及小程序页面、JSON 配置或 API wrapper 时执行：

```bash
pnpm verify:miniprogram
```

提交前完整检查：

```bash
pnpm verify
git diff --check
```

也可以直接执行根目录脚本：

```bash
pnpm verify:precommit
```

涉及生产构建或发布前，还要执行 PayloadCMS 构建检查，并使用开发环境变量占位，不提交真实密钥：

```bash
PAYLOAD_SECRET=dev-local-build-secret DATABASE_URL=postgres://ulink:ulink_dev_password@localhost:5432/ulink pnpm --filter @ulink/cms build
```

## 完成定义

- 真实失败会被暴露为错误、空状态或待配置状态，而不是被 mock 盖掉。
- 新增或修改的业务边界有测试覆盖，至少覆盖本次改动真正影响的路径。
- UI 从目标用户视角能理解下一步是什么，没有运营侧、后台侧或供应商侧的内部文字。
- 订单、会员、支付、认证和内容发布状态都以后台持久化数据为准。
- 文档已同步更新，后续继续开发时能知道当前口径。
