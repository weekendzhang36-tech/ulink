# U Link 产品说明

## 产品定位

`U Link` 是一个以微信小程序为主要载体的青年成长服务产品。

长期方向是从校园场景出发，逐步连接职业规划、实习实践、金融职业资源、本土文化内容和国际交流机会。第一阶段不追求完整生态，而是先完成一个可以真实运营和收款的 MVP。

产品模块口径以 `docs/product-modules.md` 为准。首页、客户演示原型和后续内容入口应优先使用“职业规划、实习实践、金融底色、文化交流”这一组模块表达，不要临时生成未确认的具体栏目。

## MVP 目标

第一版 MVP 的目标是验证三个核心能力：

1. 学生可以登录并建立基础会员身份。
2. 学生可以加入会员并通过微信支付完成购买。
3. 平台可以围绕金融职业方向持续发布内容、承接咨询和转化服务。

## 第一版自研范围

### 学生与会员

- 微信登录。
- 首次登录必须完成手机号验证和基础资料完善，不能跳过。
- 学生认证状态展示。
- 指导员轻量审核学生资料。
- 会员加入。
- 会员状态、有效期、权益展示。
- 会员订单和支付状态查看。

### 学生登录与认证

第一版注册认证先面向广东金融学院新生落地，但产品设计必须按多学校模型处理。学生端仍需要选择学校；第一版只是学校列表里先只有“广东金融学院”，后续可扩展多个学校。

学生首次进入小程序时必须完成完整注册链路：

1. 微信登录。
2. 授权微信绑定手机号；如果无法授权或微信未绑定手机号，则通过短信验证码验证手机号。
3. 补全真实姓名、性别、生日、学校、学院、专业、班级。
4. 勾选《用户协议》和《隐私政策》。
5. 提交资料后进入“资料已提交”成功页。

注册流程不能跳过。用户中途退出时，小程序用本地缓存保存注册草稿，下次进入恢复到上次进度；服务端只保存已提交的完整资料。

资料字段规则：

- 姓名要求填写真实姓名，不做证件强校验。指导员确认会承担轻量校验作用，学生端不使用过重的警告文案。
- 性别必填，选项为“男 / 女 / 不透露”。
- 生日必填完整年月日，仅用于年龄段判断、活动适配和基础画像，不公开展示。
- 学校、学院、专业、班级必须从后台维护的数据中选择，不允许学生手填。
- 手机号允许后续修改，但必须重新通过微信手机号授权或短信验证码验证；新手机号不能已绑定其他学生账号。

### 学生认证状态

学生提交资料后可以直接进入小程序首页，不需要等待后台审核。认证状态第一版不影响首页和基础内容浏览。成长计划会员购买、继续支付、内容报名和活动预约需要学生认证状态为“已认证”；待认证或需确认状态下，学生端引导查看认证进度并等待确认，不拉起微信支付，也不提交预约记录。

状态规则：

- 待认证：学生资料已提交，等待指导员确认。
- 已认证：指导员已确认学生资料。
- 需确认：学生资料被指导员标记为异常，学生端不直接显示“异常”字样。

学生端只在“我的”或个人信息入口显示状态标记。待认证状态展示为“待认证”；异常状态对学生展示为“需确认”。点进个人信息页后，再展示说明文案，引导学生检查姓名、学院、专业、班级并重新提交，或联系指导员。

学生被标记为需确认后，可以修改资料并重新提交；重新提交后状态回到“待认证”。学生已认证后，如果修改真实姓名、学院、专业或班级，状态重新变为“待认证”；修改生日、性别不触发重新确认；修改手机号需要重新验证手机号并重新匹配权限。

### 指导员认证管理

第一版需要让指导员参与学生资料确认，但保持轻量。

指导员由 PayloadCMS 后台在批量导入班级数据时同步配置手机号。一个班级可以绑定多个指导员，一个指导员也可以负责多个班级。指导员使用微信登录小程序并授权同一手机号后，自动获得对应班级的管理权限。

指导员权限与当前已验证手机号绑定。用户换绑手机号后，系统立即按新手机号重新计算指导员权限，原手机号对应权限失效。

指导员只能查看和操作自己负责班级的学生。超级管理员可在 PayloadCMS 后台查看和处理全部学生。

指导员入口：

- 固定入口放在小程序“我的”页，仅指导员可见，名称可为“学生认证管理”。
- 如果当前指导员有待认证学生，首页可显示轻量入口和待认证总数；无待认证任务时首页不显示。
- 首页只显示待认证总数；进入认证管理页后支持状态和班级筛选。

指导员认证管理页第一版支持：

- 状态筛选：全部 / 待认证 / 已认证 / 异常。
- 按班级筛选。
- 查看学生真实姓名、完整手机号、学院、专业、班级、提交时间、确认状态。
- 批量确认学生。
- 单个标记异常。
- 确认或标记异常都不强制填写备注。

指导员首次进入管理入口前，需要确认《管理端数据使用承诺》，说明学生姓名、手机号等信息仅用于班级管理、认证确认、活动组织等必要场景。

如果某个班级未配置指导员，学生仍可提交成功并进入“待认证”；PayloadCMS 后台标记为“未分配指导员”，由超级管理员补充指导员或直接处理。

### 认证消息提醒

第一版不接服务号通知。小程序内使用订阅消息作为增强提醒，但不作为流程强依赖。

指导员进入“学生认证管理”页时，页面可显示“接收待认证提醒”按钮。指导员点击后调用小程序订阅消息授权；授权成功后，下一次有学生提交认证资料时，通过微信服务通知提醒指导员。订阅失败或拒绝不影响管理页使用，页面仍保留红点和待认证数量作为主提醒。

学生提交资料成功页显示“资料已提交”，并提供两个动作：

- 接收认证结果通知。
- 进入首页。

学生点击“接收认证结果通知”后授权小程序订阅消息。指导员确认通过或标记需确认时，两种结果都发送认证结果通知；如果学生未订阅，则只在个人信息页查看状态变化。

### 微信支付

- 会员购买支付。
- 支付成功后的会员状态更新。
- 订单状态记录。
- 必要的支付失败、取消、超时状态提示。

### 成长服务内容

第一版内容方向先围绕产品模块图中与 MVP 最相关的成长服务入口展开：

- 职业规划：测评、规划、简历与课程支持。
- 实习实践：实训营、岗位介绍与实践机会。
- 金融底色：金融沙龙、财商课与机构资源。
- 文化交流：非遗文化、中外交流与研学路线。

这些模块是产品地图和服务方向，不代表第一版全部已经上线。学生端文案应避免“第三方协作”等运营视角表达，也不要把未确认能力写成已经开放的栏目。

### 运营管理

MVP 需要支持最基础的运营动作：

- 管理会员套餐、价格、权益和上下架状态。
- 管理内容分类与内容发布。
- 查看会员订单和支付状态。
- 配置咨询入口或第三方服务跳转入口。

后台管理第一版优先放在 PayloadCMS Admin 中完成。会员、支付、订单、内容和学校数据等第一版业务逻辑也可以先集中在同一个 PayloadCMS 项目内，后续复杂度上升后再拆独立服务。

## 第三方服务范围

以下能力第一版不自研，优先接入第三方服务：

- 简历制作、简历优化、简历投递辅助。
- 职业测评、性格测评、能力测评。
- 其他已有成熟工具的专业职业服务。

小程序内只需要提供清晰的服务入口、说明、跳转或咨询转化，不在 MVP 中开发完整测评系统或简历编辑器。

## 暂缓范围

以下模块属于后续生态扩展，不进入 MVP 主链路：

- 非遗文化内容、非遗路线和线下体验。
- 研学/游学、中外文化交流、SWT-J1 等跨境项目。
- 更完整的实习实践网络。
- 自主创业出口。
- 大型合作伙伴生态和复杂资源 marketplace。

这些模块可以在信息架构中预留，但不应影响第一版的上线速度。

## 首批用户

第一版主要服务对象是对金融行业、职业规划、实习实践感兴趣的学生群体。

用户可能处于高中后期、大学或初入职场阶段，但 MVP 应优先围绕大学生和即将进入职场的学生设计。

## 核心用户路径

1. 学生通过微信进入小程序。
2. 学生授权登录并完善基础资料。
3. 学生浏览金融职业内容和会员权益。
4. 学生购买会员并完成微信支付。
5. 支付成功后获得会员身份和对应权益。
6. 学生进入金融职业内容、咨询入口或第三方简历/测评服务。

## 设计方向

界面默认坚持 Apple iOS 风格：

- 浅色系统背景。
- 分组表单和清晰层级。
- 克制圆角和细分割线。
- 蓝色主操作按钮。
- 内容页和会员页保持轻量、清晰、可操作。

小程序第一屏应直接呈现可用功能，不做营销式落地页。

## 待确认问题

- 第一批金融职业内容分类和栏目名称。
- 会员套餐数量、价格、有效期和权益。
- 微信支付商户号和结算主体。
- 简历/职业测评第三方服务供应商。
- 学院、专业、班级的首批导入数据格式。
- 小程序订阅消息模板名称和审核要求。
- 腾讯云部署形态、域名、数据库和对象存储规格。
